# 已发布知识的读取资格

2026-10-28，关闭已记录的跨存储发布可见性缺口。服务对象是获得政策答复的客户，以及维护版本、追查回答依据的知识运营者。

## 决策与证明范围

外部索引写入不是发布成功。新取得的文档证据必须匹配数据库中已提交的 `Document.is_active`、`active_version_id` 和实际 `DocumentVersion.document_id`；未登记、缺少版本或与 active 不符的候选均不能进入新检索上下文。已经发布的 partial 版本重试时，attempt 状态可变为 processing/failed，不能仅据此撤销仍由 active pointer 指向的版本。

每批资格判断只执行一条 JOIN SELECT，不按命中逐条查询，也不缓存“未登记”许可。数据库读取默认最多等待 3 秒；失败、超时为明确的不可用，不回退成 legacy 许可。客户路径据此使用既有中英文检索降级回复；文档搜索和图查询接口返回固定 503 提示。

有文档证据的缓存命中也增加登记查询，不再意味着请求完全跳过数据库。FAQ 和纯寒暄可独立工作；本轮没有延迟、容量或数据库负载成绩。

这里的快照是**获取证据时的已提交登记**。同一次判断覆盖该批所有候选，但不同读取、回答生成和不同请求不构成一个分布式事务。已经开始的流不会因后来发布而撤回旧 token，历史引用仍保存回答当时的版本。它也不证明模型逐句正确、索引文本未被第三方篡改，或任意图查询具有完整事实归因。

[PostgreSQL 16 的隔离说明](https://www.postgresql.org/docs/16/transaction-iso.html)支持按单条语句读取已提交快照；不能把 Read Committed 下的多个 SELECT 称为同一快照。这是设计依据，SQLite 测试不是 PostgreSQL 并发执行证据。

## 覆盖哪些路径

| 路径 | 行为 |
|---|---|
| 向量、BM25 与 RRF | 有界扩大候选池，合并两腿后统一判断，在融合和交付截断前移除不合格候选 |
| BM25 warmup、刷新、本地发布 | 只加入已登记发布的 chunk；预提交候选不进入索引，提交后的 epoch 让下一次读取重建 |
| 普通 RAG 与 Agent 知识工具 | 生产初始化将同一 guard 注入 Hybrid；节点消费和缓存读回再次检查，检索不可用不伪装成有证据 |
| L0、L1 知识回答 | 引用与来源整体合格才重放；不能只删掉坏引用、保留使用了它的正文 |
| L2 检索缓存 | 一条候选不合格就重新检索，补充当前可用结果 |
| 图结果 | 根据真实版本归属核对独立来源集合，绝不 zip 成文档/版本映射；缺来源、混合失效或来源不完整时整条拒绝 |
| 文档搜索、自然语言图查询 | 不经过聊天也执行同一资格判断；认证要求不变 |

有界候选池仍可能被大量无资格点占满，因此不保证返回请求数量，也不声明无限候选下的完整召回。原始外部索引允许保留失败候选用于恢复，但它们不是客户可用证据。重复判断并不提供跨判断原子性。

这些是随应用启动的生产入口。手工构造的内部检索/图组件仍可不带 guard，用于原始存储操作、合成评测等；自定义集成必须显式传入同一发布策略，不能把原始 VectorClient 返回值当成已经审核的客户证据。

图来源收集现在传播 `provenance_incomplete`：形状不合法或达到遍历/数量限制不会被静默裁成“完整来源”。来源集合达到 50 项也按不能确认完整处理，可能保守拒绝确实完整的 50 项图结果。Qdrant 的 vector/scroll 适配在覆盖字段前保留身份冲突标记，避免原始 document/chunk/version 不一致被规范化掩盖。

FAQ 是独立维护的明确引用源，不伪装成 DocumentVersion。L1 仅对 intent 明确为 greeting/chitchat 且来源与引用均为空的纯会话保留缓存；扩大的策略 allowlist 不能让无引用 policy 回答绕过校验。原有上下文资格、声明和输出检查继续执行。

## 缓存与发布恢复

L0/L1/L2 使用固定 `published-v1` 命名空间。旧缓存可能已丢掉图来源完整性信息，因此不靠重新解释旧 payload 进行迁移；旧条目不读取、不批量删除，按原 TTL 回收。L1 写入和差评驱逐共用命名空间常量，避免换 namespace 后只删旧 hash。

外部写入后仍旋转 epoch；worker 在登记事务提交后再旋转一次，等待上限 1 秒。epoch 不可用不撤回已提交发布，正确性由每次读取资格保证，不能依赖 Redis 成功或 TTL 到期。知识发布仍不是 PostgreSQL、Qdrant、Neo4j 事务：如果旧索引已删除而登记提交失败，可能暂时没有答案；恢复同一 processing job 或重试失败版本后重新取得资格。

## 旧语料与上线边界

现代 `seed_demo_kb` 已走持久化任务。更旧的、只在 Qdrant/图里存在的未登记内容，本规则下不再用于新客户回答。运营者应保留原始文件，用相同 `document_id` 通过既有上传/导入任务重新处理，确认 `indexed` 或可接受的 `partial`、active pointer 和来源读回后再验收；不要手工把旧点标成已发布。

现有表足够表达资格，没有新增数据库迁移。滚动更新期间旧二进制仍可能使用旧规则；只有所有服务实例更新完成，才能把本合同作为整体线上行为。未在本轮执行部署。

| 考虑的方案 | 取舍 |
|---|---|
| 只改失败标签或只旋转缓存 epoch | 不能阻止底层候选进入新检索，拒绝 |
| Qdrant collection alias 切换 | 适合整集合切换，不能独自协调登记、BM25 与图，未采用 |
| 准备、激活、退休三阶段写入及清理任务 | 可进一步保留旧版可用性，涉及图双版本和故障恢复协议，仍是后续增强 |
| 已提交登记的读取资格 | 本轮采用；允许明确暂不可用，阻止未发布候选成为新证据 |

[Qdrant 官方 alias 说明](https://qdrant.tech/documentation/manage-data/collections/#collection-aliases)描述整集合 alias 的原子切换；上表对多存储边界的判断是本项目架构推论，不是厂商对本项目的保证。

具体前后证据与当前门禁见[发布资格验证](../reviews/knowledge-publication-results-2026-10-28.json)。真实 PostgreSQL 并发、Neo4j 查询与生产模型质量仍需独立验证。
