# 回答参考资料快照

2026-10-17。本契约贯通检索、普通 RAG/Agent/FAQ 回答、缓存、REST/SSE、持久化历史及 portfolio-fe 客服界面。

## 用户能核验什么

`citations` 保存本轮实际提供给生成过程的参考资料，FAQ 则保存所返回的审核答案。它不是逐句事实判定，也不是模型自行生成的书目。界面将其标为“参考资料”，允许展开阅读片段和版本、页码、章节信息。

文档更新后，历史答案仍显示生成时的版本和片段，不查询并替换成当前版本。删除知识文档会清理检索索引和原件，但不会追溯修改已经持久化的聊天内容及其引用快照。删除源文档不等于删除聊天记录；需要删除对话内容时应使用对话清除接口。该接口清理会话消息及摘要，不删除用户事实或客服工单；它等待本进程已经调度的本会话后台写任务，尚不提供跨进程或与新轮次同时写入时的删除屏障。没有版本记录的旧来源不会被猜测绑定到最新版本。

## 数据契约

保留兼容字段 `sources: string[] | null`。新增 `citations` 数组，最多 20 条，由 `SourceCitation` 白名单规范化；缺失、错误条目和额外内部字段不会进入公开引用。

| 字段 | 含义 |
|---|---|
| `source_type` | `document`、`graph` 或 `faq` |
| `document_id` / `version_id` / `chunk_id` | 已有逻辑文档、不可变修订和片段身份；缺失则省略 |
| `faq_id` | 审核 FAQ 身份；其 `version_id` 为问题及答案内容的 SHA-256 快照摘要，不能用于文档下载 |
| `title` / `section_path` | 当时资料标题和章节路径 |
| `excerpt` | 参考片段前 800 个字符；较长原片段会截断，偏移仍定位完整原片段 |
| `page_start` / `page_end` | 一基 PDF 页码，首尾都包含；没有页码的来源不编造页码 |
| `start_pos` / `end_pos` | 保留规范化文本中的零基字符位置，右端不包含；不是字节、token 或 PDF 坐标 |
| `source_document_ids` / `source_version_ids` / `source_chunk_ids` | 图资料的独立来源集合；数组之间没有按序配对保证 |

图检索可能综合多份资料，片段是图检索提供的描述，不冒充原文逐字摘录。缺少来源的历史图实体仍可以显示综合内容，但不虚构文档、修订或下载链接。向量与关键词结果的文档片段保留其实际修订和位置。

任意上传者身份、临时路径和原始 metadata 不会透传。启用输出安全检查时，标题、章节或片段被阻断或需脱敏的整条引用会被省略；不将改写文字伪装为原文片段。模型失败、转接/确认模板，以及被安全或事实门禁替换的回复不附上原回答的引用。

## 传输与存储

- `POST /api/v1/chat` 与 `GET /api/v1/chat/history` 每条助手消息提供 `citations`，无参考资料时为空数组。旧历史仍保留已有 `sources`，不补造版本。
- `POST /api/v1/chat/stream` 默认保持原文本流协议。请求增加 `include_citations: true` 后，完整响应在 `[DONE]` 前额外发送 `event: citations`，JSON 数据为 `{"citations": [...]}`。错误、超时和中断流不发送最终引用事件。
- 客户端须按 SSE 事件名分流；未知具名事件不能混入正文。portfolio-fe 使用显式 opt-in，并恢复真实 `/chat/history` 的来源快照。
- 引用以 JSON 保存到助手消息 metadata，无需新增数据库列。历史读取不访问当前知识库来重建引用。
- L0/L1 缓存与回答一同序列化引用；旧 payload 无此字段时返回空数组。知识库 epoch 变化仍使旧答案缓存失效。L1 仍仅服务原有小聊 intent 范围，没有因支持字段而扩大缓存适用面。

管理端原文下载仍要求原有知识库写权限；聊天引用不附加无权限的下载链接，也不扩大原文访问边界。

## 方案依据与验证边界

[Anthropic 的引用文档](https://platform.claude.com/docs/en/build-with-claude/citations)区分文档位置和引用文本，并提供与具体回答断言对应的原生引用能力。这里借鉴明确位置语义，采用本项目多模型共用的参考资料快照；没有接入该供应商能力，也不宣称达到逐断言引用验证。

回归覆盖真实导入→本地 Qdrant/混合检索→编译对话图→L0 缓存→SQLite 历史→换版/删除；REST/SSE 在 ASGI 与真实持久化间验证一致性。模型和外部 Redis 由确定性替身隔离，因此这些检查证明来源生命周期和接口契约，不证明真实模型对资料的理解或每一句答案的正确性。
